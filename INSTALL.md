# Installing `jmp` on a new machine

This guide reproduces the exact setup that works on the original machine: an
**editable `uv` tool install** that puts a `jmp` command on your `PATH` while
running straight from this source directory.

If you're an AI agent asked to "install it just like it's installed on the other
machine" — follow [Part 2](#part-2--the-install). Read the
[gotchas](#gotchas-that-will-bite-you) first; three of them cause silent
failures that look like the app is broken.

---

## Part 1 — Before you start

### Getting the project onto the USB stick

USB sticks are usually formatted **exFAT or FAT32**, which support neither
symbolic links nor Unix permissions. Use a **git bundle** — one ordinary file
carrying the entire repository and its history:

```bash
# On the source machine, from the project dir:
git bundle create /media/usb/jmp.bundle --all
```

That's ~100 KB. On the new machine:

```bash
git clone -b android /media/usb/jmp.bundle jmp
cd jmp
```

This is the recommended route on a FAT/exFAT stick. A bundle is a single regular
file, so there are no symlinks, permissions, or case-sensitive names to preserve,
and it drops you straight onto the correct branch with full history and both
branches intact. It also can't carry the machine-specific junk described below.

<details>
<summary>If you'd rather copy the folder directly</summary>

That works too — the tracked source tree is FAT-safe (verified: no symlinks, no
case-colliding filenames, no illegal characters, no executable bits that matter).
**The only symlinks in the project live in `.venv/`**, which you must delete
anyway. Delete the three directories below *before* copying, and the copy will
complete without symlink errors.

Two caveats versus a bundle: copying `.git/` file-by-file across FAT is slower
and more fragile, and an untracked-file copy loses nothing here only because this
project has no tracked symlinks — don't assume that for other repos.

</details>

### Machine-specific directories to delete

**Skip this if you cloned a bundle** — a fresh clone can't contain any of it.
If you copied the folder, three directories are machine-specific and must be
deleted rather than reused:

```bash
rm -rf .venv build jet_music_player.egg-info
```

- `.venv/` — 110 MB, contains Linux-x86_64 binary wheels (numpy, pygame) and is
  useless on a different OS/architecture. It is `.gitignore`d for this reason.
- `build/`, `*.egg-info/` — stale packaging artifacts that can shadow a fresh
  install.

Deleting these costs nothing; everything in them is regenerated by the install.

> **Sanity check:** confirm you're on the right branch. The Android/mpv work
> lives on the `android` branch, which is **one commit ahead of `master`**
> (`d154b99`). That commit is what makes `pygame` optional. Run `git branch` and
> `git log --oneline -1`.

### System prerequisites

| Requirement | Why | Check |
|---|---|---|
| **Python 3.9–3.13** | pygame ships prebuilt wheels only for released versions | `python3 -V` |
| **ffmpeg** | M4A/Opus playback + visualizer analysis of any compressed format | `which ffmpeg` |
| **uv** | the installer used here | `uv --version` |
| **git** | optional, only if cloning instead of copying | `git --version` |

Install them:

```bash
# Linux (Ubuntu / Debian)
sudo apt update && sudo apt install -y ffmpeg python3-venv

# macOS
brew install ffmpeg

# uv (all platforms) — or: brew install uv
curl -LsSf https://astral.sh/uv/install.sh | sh
```

ffmpeg is a **system package, not a pip dependency**. Without it MP3/OGG/FLAC/WAV
still play, but M4A and Opus won't, and the visualizer can't analyze compressed
audio. The app prints a warning at startup if it's missing.

## Part 2 — The install

From inside the project directory:

```bash
cd /path/to/jmp
rm -rf .venv build jet_music_player.egg-info
uv tool install --editable '.[desktop]' --python 3.12 --reinstall
```

That's the whole install. Then verify:

```bash
cd ~                       # IMPORTANT: leave the project dir before testing
jmp --help                 # or just: jmp
```

Testing from `~` rather than the project directory is not a nicety — see
[gotcha 2](#2-testing-from-inside-the-project-dir-hides-a-broken-install).

### Why each flag is there

- **`--editable`** — matches the original machine. The `jmp` command runs this
  source tree directly, so edits take effect immediately with no reinstall. The
  cost is that the install bakes in an **absolute path** (see gotcha 1).
- **`'.[desktop]'`** — installs pygame, the desktop audio backend. **Omitting
  this gives you a `jmp` that starts fine and then can't play audio** (gotcha 3).
  The quotes matter: bare `.[desktop]` is glob syntax in zsh and will error.
- **`--python 3.12`** — pins a Python that has a pygame wheel. Skip this only if
  your default `python3` is already in the 3.9–3.13 range (gotcha 4).
- **`--reinstall`** — makes the command idempotent; safe to re-run any time.

If `uv` doesn't have Python 3.12 available it will download it automatically.

## Gotchas that will bite you

### 1. Moving or renaming the folder breaks `jmp`

An editable install writes an **absolute source path** into its finder script
(`~/.local/share/uv/tools/jet-music-player/lib/python3.12/site-packages/__editable___*_finder.py`,
in the `MAPPING` dict). Move or rename the project directory and that path goes
stale.

**Symptom:** `ModuleNotFoundError: No module named 'jet_music_player'` from every
directory *except* the project folder itself.

**Fix:** re-run the install command from the new location.

This already happened once on the original machine, during the
`terminaltunes` → `jmp` rename (2026-07-15). It is documented in `CLAUDE.md`.

### 2. Testing from inside the project dir hides a broken install

When your shell's working directory is the project folder, Python finds
`jet_music_player/` as a **local directory** and imports it regardless of whether
the install actually works. A completely broken install looks perfectly healthy.

**Always `cd ~` before verifying.** This is exactly what masked the stale-path
bug in gotcha 1.

### 3. Forgetting `[desktop]` gives you a player with no sound

As of commit `d154b99`, `pygame` is an **optional extra**, not a hard dependency
— because it doesn't build or run under Android/Termux, where the mpv backend is
used instead.

So on desktop, plain `uv tool install --editable .` installs *no audio backend*.
The app launches, the browser works, the UI renders, and playback silently fails.

**Note for anyone comparing against the original machine:** its tool environment
*does* contain pygame 2.6.1, but only as a leftover from an install that predates
`d154b99`, when pygame was still a hard dependency. Its `uv-receipt.toml` records
no `[desktop]` extra. Copying that receipt's command would reproduce a broken
install — use `'.[desktop]'` as shown above.

### 4. Python 3.14+ can't install pygame

pygame publishes prebuilt wheels only for released Python versions (3.9–3.13 at
time of writing). On a newer Python, pip falls back to compiling from source and
fails without SDL development headers.

The original machine's system Python is **3.14**, which is precisely why both its
`.venv` and its tool environment run **3.12**. Hence `--python 3.12`.

## Verifying it actually works

```bash
cd ~                                  # never test from the project dir
which jmp                             # → ~/.local/bin/jmp
jmp ~/Music                           # or any directory with audio in it
```

Confirm the audio backend is really present:

```bash
~/.local/share/uv/tools/jet-music-player/bin/python3 -c \
  "import pygame; print('pygame', pygame.version.ver)"
```

If that raises `ModuleNotFoundError`, you hit gotcha 3 — re-run the install with
`'.[desktop]'`.

Inside the app: arrow keys browse, `→` plays, `v` cycles the visualizer, `q`
quits. If tracks list but won't play, check `which ffmpeg` and the pygame check
above.

## Alternative installs

These are supported but are **not** how the original machine is set up.

**Throwaway virtualenv** (no `jmp` command on `PATH`):

```bash
uv venv --python 3.12 .venv
source .venv/bin/activate             # Windows: .venv\Scripts\activate
uv pip install -r requirements.txt
python run.py ~/Music
```

Note that `requirements.txt` still lists `pygame` as a plain dependency, so this
path gets a working audio backend without needing the extra.

**Non-editable install** (immune to gotcha 1, but code edits need a reinstall):

```bash
uv tool install '.[desktop]' --python 3.12 --reinstall
```

**Run without installing at all:**

```bash
python run.py ~/Music
python -m jet_music_player ~/Music    # equivalent
```

## Android / Termux

A phone is a different install entirely — no pygame, no `uv`. Install Termux from
**F-Droid** (the Play Store build is outdated), then:

```bash
pkg update && pkg upgrade -y
pkg install -y python mpv ffmpeg git python-numpy
pip install textual mutagen pydub        # NOT pygame — unused on Termux
termux-setup-storage                     # grant access to your music
git clone https://github.com/EtaerioEdTech/jmp.git
cd jmp && git checkout android
python run.py ~/storage/shared/Music
```

Termux is detected automatically (`runtime.py`): it switches to the **mpv** audio
backend over JSON IPC and mounts the on-screen touch d-pad. Both can be forced
for testing on desktop:

```bash
JMP_AUDIO=mpv JMP_TOUCH=1 jmp ~/Music
```

## Uninstalling

```bash
uv tool uninstall jet-music-player
rm -rf ~/.cache/jet-music-player          # library tag cache
```
